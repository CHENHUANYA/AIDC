# 企業設備維修與知識管理共用模板實作計畫

日期：2026-09-21。狀態：設計提案，尚未實作或完成跨公司驗證。

## 目標與第一版範圍

將目前 Alarm RAG 整理成「共用核心＋公司設定包＋文件解析／資料介接模組」。目標使用者先限定為具有設備異常通報、維修工單與知識查詢需求的企業。

第一版採每家公司獨立部署、獨立資料與帳號。共用的是程式與導入格式；公司設定包不是跨公司存取控制機制。集中式多租戶、任意流程編輯器、各品牌設備即時連線另列後續工作。

新公司使用已支援的文件與事件格式時，只需設定與匯入資料；新的文件結構或通訊協定可以新增介接模組，需另行測試，不能宣稱所有 PDF 或設備皆可直接使用。

## 依序執行

### 1. 定義公司設定包

建議新增 `templates/company.example.json`，先用 JSON，沿用現有 Python 工具即可。以下為設計格式，現有系統尚不能載入：

```json
{
  "schema_version": 1,
  "company": {"id": "demo-a", "display_name": "示範工廠 A"},
  "default_collection": "cnc_manual",
  "collections": [
    {
      "id": "cnc_manual",
      "display_name": "CNC 設備手冊",
      "domain": "cnc",
      "parser": "sinumerik_alarm_v1",
      "prompt_profile": "cnc_maintenance_v1"
    }
  ],
  "lines": [{"id": "line-a", "display_name": "第一產線"}],
  "workflow": {"allow_operator_reopen": false}
}
```

以具型別的結構驗證版本、重複 ID、預設知識庫、產線參照與模組名稱。解析器與提示詞使用受控登錄名稱，不允許設定包提供任意 Python 路徑或執行指令。帳號密碼、API 金鑰與公司正式文件不放入可分享的設定範例。

明定設定來源：設定包負責初始化；初始化後，既有設定儲存層作為執行時設定來源，管理員以既有版本檢查機制更新。重新套用設定包必須先顯示差異，不能在重啟時覆寫管理員變更。

驗收：合法設定可預覽；錯誤設定指出欄位與原因；預覽不修改資料。

### 2. 打通後端到畫面的設定讀取

新增公司設定載入服務與已登入使用者可讀取的最小展示設定 API；管理員設定 API 繼續保護管理欄位。API 僅回傳畫面需要的公司名稱、可用選項與預設值，既有操作與資料權限仍由後端檢查。

將固定選單改為讀取同一份設定。公司登錄的知識庫清單與 `/collections` 的索引狀態分開表示，支援「已設定但尚未匯入」狀態。

統一後端的手冊解析規則：明確指定時驗證指定值；未指定時優先依設備對照，再採公司預設；無合法選項就回傳清楚錯誤。設備對照與明確指定衝突時拒絕或要求修正，不能悄悄查詢另一台設備的資料。

第一版保留既有 API 的 `manual` 欄位與既有知識庫 ID，在內部對應到設定中的 collection。既有事件與工單的 `manual` 不批次改名；新寫入路徑明確寫入解析後的值。資料庫預設調整需搭配遷移與相容檢查。

驗收：新增 `compressor_demo` 知識庫設定後，各角色相關選單可呈現，不修改前端程式；未建索引時顯示未就緒；既有 CNC 查詢仍正常。

### 3. 分離文件解析與回答領域

保留現有 SINUMERIK 切分行為為一個解析器，另提供通用文字型 PDF／SOP 解析器，統一輸出段落文字、來源文件 ID、頁碼、段落位置、知識庫 ID 與可選警報碼等資訊。

通用 SOP 不強制具有警報碼；字母數字混合的設備代碼也不能套用純數字規則。掃描 PDF 若未提供 OCR，匯入時應明確回報沒有可擷取文字。

將提示詞的設備領域與回答格式整理成受控設定檔，保留引用、來源區分與資料不足時的說明規則。新領域的詞彙擴充與警報碼抽取需一起檢查，避免只改提示詞卻仍用 CNC 專屬檢索假設。

驗收：既有 CNC 樣本的代碼與來源頁碼保持正確；第二領域可用自然語言查詢 SOP，能回溯正確來源，且不憑空帶入 SINUMERIK 內容。

### 4. 建立標準導入流程

依序提供設備、人員及維修紀錄的欄位規格與匯入範例：

| 範本 | 最小設計內容 |
| --- | --- |
| 設備清單 | 設備 ID、顯示名稱、產線 ID、設備型號、知識庫 ID。 |
| 人員對照 | 使用者識別、角色、產線範圍；帳號初始化沿用受控建立流程。 |
| 維修紀錄 | 原始紀錄 ID、設備 ID、異常描述、原因、處置、結果、日期。 |
| 知識文件 | 文件 ID、標題、版本、來源、適用設備／知識庫、解析器。 |

匯入先預覽，再套用；檢查不存在的設備或產線、重複識別碼與必填值，輸出可修正的錯誤清單。重複匯入的跳過／更新規則應明確且可追蹤。歷史維修紀錄沿用知識審核機制，不因匯入就自動視為核准知識。

第一個交付切片優先完成「公司設定＋設備清單」；人員與工單匯入再逐項接入現有能力，避免同時重寫所有模組。

驗收：同一份設備檔案重複匯入不產生重複設備；錯誤參照不進入正式資料；匯入結果可查。

### 5. 包裝獨立部署

提供公司設定範例、部署環境範例、初始化指令、文件匯入說明與備份還原說明。每個實例使用獨立資料庫、檔案／向量儲存、憑證與備份位置。

若兩個實例部署在同一主機，需移除或參數化固定 `container_name`，分配不同 Compose project、連接埠與持久化路徑。僅變更公司 ID 或 Compose project 名稱不足以隔離現有相對掛載目錄。

驗收：全新空目錄可依說明完成部署；A 實例重啟、匯入或還原不影響 B 實例；不打包目前公司的帳號、文件或維修紀錄。

### 6. 用兩組情境完成展示與驗證

以相同程式版本建立 CNC 工廠 A 與通用設備工廠 B 的模擬部署。B 可先使用自編空壓機 SOP 與含字母的示範代碼，明確標示模擬資料；實際操作步驟不可作為正式設備指引。

每組走完：套用設定、匯入設備與文件、查詢來源、通報異常、建立／指派工單、填寫結果、管理員審核知識、再次查詢。另測試資料不足的問題、錯誤設定與角色越權。

| 指標 | 記錄方式 |
| --- | --- |
| 導入工時 | 分別記錄資料整理、設定、匯入、必要模組開發與驗證時間。 |
| 核心程式修改 | 固定版本後，記錄導入第二情境是否改動核心；新增解析器也需如實計入工作。 |
| 查詢品質 | 各情境事先準備問題與正確來源，分開報告命中、引用正確性與資料不足回答。 |
| 流程可用性 | 兩組各角色完成同一條工單與知識審核流程。 |
| 隔離與回歸 | A 的資料不出現在 B；既有角色權限與 CNC 功能保持正常。 |

設定數量或画面換名不等於跨公司驗證；模擬驗證也不能表述為真實企業導入成效。

## 實作與驗證順序

1. 公司設定結構、驗證器、既有部署相容設定。
2. 後端讀取、動態選單、統一預設值與新增設備清單。
3. 通用文件解析與領域提示詞。
4. 匯入預覽、部署初始化與說明。
5. 兩情境流程展示、品質評估與導入成本報告。

每階段先跑與改動相關的設定、API、匯入、權限或解析測試；整合完成後再跑既有 smoke／角色流程與 RAG 評估。此文件的編寫不代表上述功能與測試已完成。

第一個可展示成果應為：同一套程式在 CNC 工廠 A 與工廠 B 顯示不同公司名稱、設備與知識庫，並可選取各自文件完成查詢。其後再完成兩組工單與知識入庫閉環。
